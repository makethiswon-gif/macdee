# Lawyer Studio

Admin route: `/admin/lawyer-studio`. Live generation was verified on an access-protected Vercel preview. The studio was deployed to production on 2026-09-11; portrait approval remains a separate action.

## Model and workflow

- Approval and blog linking remain separate permissions. When approved photos exist but `blogEnabled` is false, readiness returns `studio_blog_disabled` with the approved count and directs the user to enable the existing library switch, not to buy/regenerate/reapprove photos. Missing approval still returns `studio_approval_required`. Both conditions block paid planning and provide a profile-bound `?profileId=...&view=library` recovery link. Studio shooting/editing also shows an explicit approved-but-unlinked status. Viewing readiness or following the link never changes permissions automatically.

- `5장 세트` requests five independent photographs with one confirmation. The selected scene comes first, followed by four other scene categories; every slot has a distinct setting ID and camera/composition brief. Wardrobe, mood, people count, quality and shoot style stay consistent across the set. Individual backgrounds still receive new seeds on each new set.
- The private `batches/{id}.json` manifest freezes five deterministic child request IDs and shot briefs before preparation. All five identity/build/style reference sets must finish local preparation before the browser dispatches the first paid shot. This uses the existing image endpoint once per photograph, sequentially, not five outputs from one shared composition prompt.
- The browser displays saved/current/waiting slots and can pause after the current shot. Closing the page stops dispatching subsequent shots; it is not an unattended server worker. Reopening offers manual continuation from the same server manifest. Saved assets are skipped, uncertain paid outcomes retain the original child ID, and errors stop the remaining queue. No automatic replacement request or approval is added. Existing single-shot requests, frozen jobs and 96% head-balance policy remain unchanged.
- `GET/POST /api/admin/lawyer-studio/batch` requires administrator authentication and existing Origin checks. Five-shot preparation requires explicit `count: 5` payment consent. A stored batch can be resumed only under its owning profile. The new route traces the same private style JPGs and face cascade as single-shot preparation. No new database schema or provider is introduced.

- Direct OpenAI Images **edits** API, pinned to `gpt-image-2.5-sunburst-2026-09-08`.
- One explicit paid request produces one PNG, 1536x1920, `xhigh` or `max`. There is no hidden model fallback, reviewer or paid automatic retry.
- Select 1-3 identity originals and up to 2 style references. New jobs send uncropped same-person body-build sources FIRST, isolated head crops second, then actual style images in separate role groups. Registered profile images remain unchanged. Uploaded images accept single-frame JPG/PNG/WebP, up to 3MB and 24 million decoded pixels.
- Default mood is natural color (`documentary`) with a color-preserving editorial finish. Muted color and explicitly selected monochrome remain available. Monochrome reference photos contribute luminance/texture, not forced grayscale. Saved filters, approved photographs and frozen jobs are not migrated.
- Scene includes a studio with controlled side lighting. Shooting style includes GQ-inspired Korean fashion editorial direction without mastheads or affiliation claims. One-person and two-person reference modes prevent treating a joint firm portrait as one blended identity.
- Preparation freezes references, prompt, model, options and a request hash. The same request ID cannot change its inputs.
- New shoots now receive a fresh background brief: room structure, materials, furniture, camera viewpoint and motivated lighting vary independently of the identity references. Forty-eight setting directions span six scene categories; the last three completed settings in the same category for that lawyer are excluded. Style references guide texture and tone, never reconstruct their scenery. The brief is saved on the job and asset, so retries and old jobs keep their original scene without rebilling.
- New shoots in the five original scenes use an environment-first long shot: approximately 20% person / 80% surrounding space by image area, not height. For joint portraits both people share that 20% target. This framing applies across editorial/GQ styles and reference/no-reference paths, overriding tighter reference crops or additional directions. Camera distance changes, not anatomy; full standing/seated figures and readable Korean settings remain required. The ratio is a model composition target, not a measured pixel guarantee, and no automatic paid regeneration is added. Existing photographs and frozen jobs retain their previous framing. The shooting settings display the new-shot target.
- The `forbes` scene is an explicit owner-requested exception: a prominent knee-up business-magazine portrait, with visible figure height around 75-85% of the frame. Eight Korean interior/set directions and four cover framings vary across shoots. Identity, age, natural proportions and the selected mood stay intact; two people share a balanced paired cover. No Forbes logo, masthead, rankings, badges or actual-publication claim is generated. The scene controls framing even with GQ styling. Its UI label is `포브스 · 잡지 메인`, with a person-led cover target instead of the 20:80 label.
- Generated originals are immutable. Sharp applies deterministic exposure, contrast, saturation, grain, softness, highlight compression, vignette, output size and JPEG quality. Preview and export derive from the same full-resolution processing.
- Approval confirms likeness, anatomy, setting and usage rights. Changed pixels invalidate approval. Generated pictures are labeled as staged AI portraits, not records of actual offices or consultations.

## Independent reference and shot preparation

New jobs use `body-first-references-v3`. OpenCV's bundled frontal-face cascade detects heads locally, with a conservative consensus threshold to reduce false positives on ties/hair. Each selected original must contain exactly the selected one or two faces at adequate resolution. Two-person originals produce separate head crops; a prompt groups each consecutive pair and preserves both identities. Crops retain hair/ears and minimal shoulders. A failed or ambiguous detection still stops before payment; adding an uncropped build reference is deliberate, not a fallback for failed face detection. This is face detection, not identity recognition. The administrator still reviews previews and resulting likeness.

`natural-scale-v3` establishes body geometry before face detail: approximately 7-7.5 head lengths for a standing figure, credible shoulder width, intact seated hip/thigh geometry and short-telephoto distance. These are photographic direction guides, not claims about the lawyer's real height. Normal long shots target a 9-10.5% head height; Forbes now uses knee-up framing and a 14-17% head height. Seated camera height follows the seated torso. Natural anatomy overrides an exact 20:80 area target. Existing photographs, filters, approval states and frozen v1/v2 jobs are not migrated.

After the paid original is safely stored, local face detection records a free framing review. Face-box height above 7.8% (normal) or 12.5% (Forbes) flags an original for manual proportion review; missing/ambiguous detection is explicitly unmeasured. A face box excludes hair and is not a head-to-body anatomy measurement. This heuristic never approves, discards or automatically regenerates a photograph. The editor identifies the original review separately from retouching.

New jobs freeze `gentle-head-balance-v2`. Following owner review, the initial head reduction is now fixed at 4% (96% scale), instead of the former 2-10% adaptive reduction. It applies only when the expected faces are detected and exceed the framing threshold. Missing/tiny detections, clipped boundaries, overlapping paired regions and unexpected closeups receive no automatic geometry changes. No body stretching is performed. The immutable original and explicit editable head regions remain available; deleting the region restores the original geometry. The feathered region can move nearby scenery, so this is a conservative starting correction, not an anatomical certification. Frozen v1 jobs retain their original finishing policy; existing photographs are not migrated automatically.

`POST /api/admin/lawyer-studio/reference-preview` performs authenticated local preparation and returns separate private `faces`, `bodies` and `styles` previews. Actual style pixels now reach the provider; Sharp's measured tones only supplement them. Ten owner-supplied references live in `lib/lawyer-studio/style-references/`, outside `public/`. With no custom style selected, two scene-appropriate references are selected deterministically by profile and scene. Custom selections replace that pair. Both preparation routes explicitly trace these assets for serverless deployment. They are never published as blog images.

Role-numbered instructions use faces for identity, full sources only for visible physique, and style references for composition, negative space, depth, lighting and texture. Style people's identities, literal poses, magazine branding and printed instructions must not transfer. Normal full-figure camera height follows the subject's waist/lower chest, including when seated; the larger Forbes cover uses level upper-chest perspective. The prompt rejects inflated heads, narrow shoulders and shortened limbs without imposing a slim or idealized body. The optional bounded initial head correction described above uses no paid reviewer or regeneration. Natural anatomy and likeness remain probabilistic and require owner review.

Results are cached by policy, source bytes, role and people count in `reference-analysis/`. Every prepared job freezes all image bytes and the prompt; old `isolated-references-v1` jobs keep their original inputs. Preview and generation use the same scene selection. Local preparation costs no model tokens; sending additional real reference images increases image-input tokens in the one explicitly approved generation request.

`independent-shot-v1` defines six actions per scene (36 total), plus independent camera, gaze and composition choices. The last three completed same-scene/same-people poses and exact camera/gaze/composition combinations for that profile are excluded. The selected shot replaces the background planner's legacy framing so the two briefs do not conflict. General 20:80 and prominent Forbes framing remain unchanged. Jobs/assets record the shot; same-job recovery keeps the frozen plan, and preexisting jobs keep their full original inputs and prompt. This reduces reference composition anchoring; it cannot guarantee identical faces or perfect adherence in probabilistic image outputs. Parallel unfinished jobs and pre-release photos have no completed-shot history to exclude.

The OpenCV XML is pinned to upstream 4.12.0, licensed in-place, and explicitly included in Next server traces for both preparation endpoints and the generation endpoint's free framing review. No new DB schema or paid provider is required. All existing photographs and blog bindings are preserved.

## Storage and recovery

Existing private Supabase bucket: `owner-briefings`. No database migration is required.

`lawyer-studio/{profileId}/` contains references, frozen inputs, jobs, originals, renders and immutable numbered library revisions. All studio routes require admin authentication. Mutations check Origin when present. Library writes use optimistic revision checks.

Provider responses and claims reuse `blog-paid-operations`. A timeout or an unknown outcome never unlocks a paid claim. The same-job recovery reads the existing result; a new shoot requires separate explicit cost confirmation. Failed rendering or storage after a saved provider response is recoverable without another model call. If the provider response itself was lost, manual investigation or an explicitly paid new job may still be necessary.

Runtime secrets: `OPENAI_API_KEY`, `ADMIN_TOKEN_SECRET`, existing Supabase service configuration. Standard blog planning also uses `ANTHROPIC_API_KEY`. Never expose these in client code. Model availability is checked before a new studio job; actual access must be verified in the deployment account.

## Proportion retouching

The editor supports up to four manually placed head/body regions, including separate regions for joint portraits. Region controls support pointer placement, dragging, keyboard movement and numeric bounds. Head scaling is uniform at 85-115%; body width is 90-110% and local body length is 92-108%. These are local geometric corrections, not pose-aware height measurements or face detection. Nearby scenery inside the selected ellipse can also move and must be visually reviewed.

OpenCV.js 4.12 remaps inverse coordinates with a fixed, feathered region boundary; Sharp applies the existing tone/grain/export pipeline afterwards. This follows the [OpenCV remapping API](https://docs.opencv.org/4.x/d1/da0/tutorial_remap.html). Preview and save start from the immutable original, use the same final-resolution transformation, and never call a paid model. Region settings are stored on the asset, not frozen paid jobs. Missing settings on older clients preserve existing proportions; an explicit empty list restores unwarped geometry. Changed output pixels invalidate approval and stale blog bindings. Position-only edits at neutral scale persist without revoking unchanged pixels.

Generation prerequisites are now displayed beside the disabled generation button, including missing reference selection, rights/payment confirmations, limits and pending-job recovery.

Approval now opens an explicit review confirmation directly from the saved photograph's approval button, replacing the hidden prerequisite checkbox. Cancelling sends no request. Dirty edits still block approval with a visible save-required reason, and original comparison switches back to the saved rendering before confirmation. The server still requires `approvalConfirmed: true` and a matching library revision. Approval alone does not enable blog use or publish a photo.
