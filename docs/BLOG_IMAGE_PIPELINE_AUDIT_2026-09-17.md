# 블로그 이미지 자동 생성 — 오류 수정·점검·속도 기획 (2026-09-17)

> 대표 요청: "원고 생성 후 자동으로 나오는 이미지에서, 두 번째 이미지에 강점을 넣으면 실패하는 경우가 있다. 이미지 메뉴에서 따로 하면 괜찮다. 고치고, 다른 오류와 속도·간편화 방안도 기획하라."

## 1. 고친 것

### 1.1 강점을 넣으면 이미지가 한 장도 안 만들어지던 문제 — 원인 확정, 수정 완료

**증상**: 발행 화면에서 원고 생성 후 "카드 만들기"를 누르면 실패. 같은 원고를 이미지 메뉴에서 돌리면 성공.

**원인**: 원고 작성 단계는 주제에 맞는 승인 강점을 **최대 2개** 고른다. 모델은 글의 흐름상 **1개만** 본문에 넣는 일이 잦다(자격 문장 두 개를 연달아 쓰면 어색하다). 그런데 발행 화면의 이미지 단계는 맨 처음에 강점 확인 API(`/api/admin/blog-strengths/select`)를 호출하고, 이 API는 "고른 강점이 **전부** 원고에 있어야 한다"고 검사해 **422로 거절**했다. 여기서 막히면 기획도 생성도 시작되지 않아 이미지가 0장이 된다.
이미지 메뉴는 이 API를 거치지 않고, 본문에 실제로 들어 있는 강점만 인식하므로 통과한다.

**증거**
- 운영 로그: `blog-strengths/select` 422가 14건. 2026-09-17 18:28~18:31(KST)에 연속 발생.
- 승인 강점이 있는 프로필(유지은 변호사)에서만 발생. 9월 13일 이후 원고 6편 중 3편이 이미지 0장.
- 재현: "아버지 병원비를…" 원고 — 선택 2개(`licenses`, `specialties`) 중 본문 반영은 `specialties` 1개 → "승인 문구 미반영: licenses" → 422. "양육비 넉 달째…" 원고도 동일 구조.

**수정** (`lib/blog-strengths.ts` `reconcileStrengths`)
- 원고에 실제로 들어간 승인 문구만 선택에 남긴다. 빠진 것은 오류가 아니라 "이번 글에서 쓰지 않은 강점"으로 제외한다.
- **같은 문구의 반복은 계속 차단**한다(광고 규정·중복 방지 취지 유지).
- 적용 위치 3곳: 원고 생성 직후(저장되는 선택 자체를 바로잡음), 강점 확인 API(이미 저장된 예전 원고 구제), 이미지 컨텍스트(예전 서명 토큰 호환).
- 빠진 강점이 있으면 발행 화면 검수란에 "선택한 승인 강점 N개는 원고에 들어가지 않아 제외했습니다. 이미지 제작에는 영향이 없습니다"로 알린다.
- 강점 지시문에 "여러 개가 주어져도 흐름에 자연스러운 것만 넣는다"를 추가.
- 검증: 막혀 있던 실제 원고 2편 모두 수정 로직에서 통과(남는 강점 1, 검수 이슈 0). `test-blog-strengths` 기대값을 새 규칙으로 갱신하고 반복 차단 단언을 추가.

### 1.2 두 번째 카드만 빠지던 문제 — 저장소 일시 오류에 재시도가 없었다

- 운영 로그 2026-09-17 18:21(KST): `POST /api/admin/blog-posts/images` **500**, 메시지 `업로드 실패: …/02-info-….png`(오류 메시지 빈칸). 해당 원고는 표지·상담 카드만 저장되고 두 번째 카드가 빠졌다.
- 이 카드의 제작 체크포인트는 `complete · 레이아웃 통과 · 서명 있음`이었다. **생성은 성공했고, Supabase Storage 업로드 한 번이 일시 실패**한 것이다.
- 수정: 카드 업로드와 제작 체크포인트 읽기·쓰기에 3회 재시도(0.4초·0.8초 간격). 같은 경로·같은 바이트의 upsert라 안전하고 유료 호출과 무관하다. 그래도 실패하면 "생성된 이미지는 보존돼 있으니 '미완료 카드 재시도'만 누르라"고 안내한다.
- 9월 15일 `generate-design` 503(`ImageProductionError`) 1건도 같은 계열(체크포인트 저장소 일시 오류)로 보인다.

### 1.3 실패 사유가 로그에 남지 않던 문제
`preflight`·`select`의 422는 응답 본문에만 사유가 있고 서버 로그는 빈칸이라 원인 추적이 불가능했다. 원고·연락처 없이 **사유 문구만** `console.warn`으로 남기게 했다.

## 5. 간편화 기획

1. **"한 번에 만들기" 버튼.** 지금은 주제 뽑기 → 선택 → 원고 생성 → 저장하고 카드 만들기 → 복사, 다섯 번 누른다. 주제만 고르면 원고와 이미지까지 이어서 만들고 마지막에 한 번 검수하는 흐름을 추가한다. 원고를 고치면 이미지가 무효가 되므로, 자동 모드에서는 **무료 카드 2장을 먼저 만들고 표지(유료)는 "원고 확정" 뒤에** 시작하는 절충을 기본값으로 둔다.
2. **8개 블로그 일괄 실행.** `blog-factory`의 월 쿼터 화면에 "오늘 분량 만들기"를 두어 프로필별로 순차 실행하고, 끝나면 검수 목록만 본다. 유료 호출은 시작 전에 총 횟수를 한 번에 확인받는다.
3. **실패를 한 줄로.** 실패 메시지를 "무엇이 / 왜 / 누를 버튼" 형식으로 통일한다. 예: "두 번째 카드 저장 실패 · 저장소 일시 오류 · [미완료 카드 재시도]".
4. **프로필 준비 상태 표시.** 프로필 선택 옆에 "스튜디오 사진 ✓ · 대표번호 ✓ · 승인 강점 13" 배지. 준비가 안 된 프로필은 고르는 순간 알려 준다(2장 D·E).
5. **강점 선택 단순화.** 작성 단계의 자동 선택을 "최대 2개"에서 **"가장 관련 높은 1개"**로 줄이면 1.1 같은 불일치 자체가 줄고 글도 자연스럽다. 2개를 넣고 싶을 때만 수동 선택.
6. **사실 확인과 이미지 검수를 한 화면에.** 발행 전 체크리스트(조문·기한·수치)와 카드 3장, 네이버 복사 버튼을 한 줄로 세운다.

## 6. 재발 방지 — 운영과 Git

1. 이 브랜치(복구분 + 원고 프롬프트 + 오늘 수정)를 main에 반영해 **Git과 운영을 일치**시키고 배포한다.
