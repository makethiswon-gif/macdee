# 블로그 이미지 V11

## 적용 범위

- 블로그 발행, 블로그 이미지, 블로그 공장의 새 이미지 제작 경로를 교체했다.
- 기존 원고/발행 이미지, 네이버 복사용 HTML과 전화 링크, 승인 강점 체계는 유지한다.
- 메인 모션/3D 및 블로그 옮기기 경로는 변경하지 않았다.
- 이 문서는 로컬 구현 기록이다. 아직 커밋·푸시·운영 배포하지 않았다.

## 제작 순서

1. 서버에서 등록 프로필과 공개 승인 강점을 다시 확인한다. 원문·강점·전화번호가 맞지 않으면 시작하지 않는다.
2. Claude Opus 5의 높은 추론 설정으로 원고 전체를 기획한다. 같은 원고·프로필의 구성안은 비공개 캐시로 복구한다. 관리자가 다시 기획할 때만 새 구성안을 요청한다.
3. 표지 / 핵심 쟁점 / 실무 정보 / 실제 변호사 상담 안내의 네 장을 만든다. 핵심 쟁점은 AI 삽화 또는 비교·절차·타임라인·체크리스트·구간 도표 중 내용에 맞게 선택한다. 동일한 도표를 두 번 넣으면 구성안 검증에서 거절한다.
4. 필요한 시각물만 GPT Image 2 High로 생성한다. 표지 외 두 번째 AI 삽화는 필수가 아니다. 한글·표·전화번호·등록된 인물/로고·승인 강점은 Canvas/Sharp로 조판한다.
5. 조판 영역의 경계·겹침을 검사하고, 완성 픽셀의 상세본과 실제 360px 축소본을 Claude가 함께 검수한다. 디자인·가독성·원고 충실도 각 4/5 이상, 심각한 문제 없음이 통과 조건이다.
6. 배치 문제는 원본을 유지한 넓은 한 열 편집으로 한 번 수정·재검수한다. 시각물 문제는 **완료된 결과의 검수 실패가 확인된 경우에만** 별도 요청에서 의견을 반영해 한 번 더 생성한다. 법률 조건/주장 문제는 자동으로 고쳐 쓰지 않는다.
7. 미통과 또는 검수 불가이면 보류한다. PNG/ZIP/네이버 복사 및 새 발행 세트의 완료 처리를 막는다. 재검수는 기존 원본을 사용하며, 성공한 다른 이미지는 다시 만들지 않는다.

## 디자인

- 변호사 ID 해시로 색·서체·지면을 임의 배정하던 방식을 폐기했다.
- 공개 강점 관리에서 명시한 지면이 우선한다. 자동값은 등록 업무 분야에 따라 선정한다: 의료·기업은 분석형 ledger, 부동산·건설은 atlas, 가족·학교 문제는 journal, 상속은 column, 회생·파산은 poster, 그 외 dossier.
- 같은 분야에 같은 자동 지면이 배정될 수 있다. 모든 변호사에게 완전히 독립적인 맞춤 브랜드를 제작·승인한 것은 아니다. 개별 지면 지정과 등록 브랜드 색을 함께 사용한다.
- 원고별로 이미지 중심/분석/한 열 안내 구성을 선택한다. 최근 기획 여섯 건의 모티프·구도·도표 종류를 참고한다. 과거 전체 발행분을 역으로 분석하거나 이미지 유사도를 계산하는 기능은 아니다.
- 핵심 본문은 1024px 출력에서 최소 40px, 즉 360px 축소 시 약 14px이다. 짧은 정보 도표는 내용에 맞춰 높이를 줄인다. 보조 표제/푸터는 이 기준에서 제외한다.
- V11 결과는 색상을 256색으로 강제 축소하지 않는다. JPEG 원본의 품질을 높이고 완성 PNG는 2.7MB 이하로 제한한다. 원본은 브라우저 응답에 중복 포함하지 않고 작업 ID로 재사용한다.

## 보존과 완료 판정

기존 비공개 Storage `owner-briefings`를 사용하며 DB 마이그레이션은 없다.

- `blog-image-plans`: 동일한 원고·등록 프로필의 구성안 복구. 전체 본문은 중복 저장하지 않는다.
- `blog-visual-history`: 최근 기획한 모티프와 표현 방식.
- `blog-image-production`: 유료 호출 전 시작 기록, 시각물 원본, 조판본, 검수 결과.
- 중복 작업 키는 기존 결과를 반환한다. 이미지 응답이 불확실한 상태에서는 자동 재과금하지 않는다. 사용자가 과금 여부를 확인한 후 명시적으로 새 작업을 시작해야 한다.
- 통과 PNG에는 서버 HMAC 서명을 발급한다. 이미지 바이트, 원고 해시, 변호사, 카드 종류, 제작 세트를 묶는다. 업로드 API는 같은 세트 네 장의 서명을 모두 확인한 후에만 ready로 변경한다.
- 구버전 업로드 호출의 호환 경로는 유지한다. 새 세 경로는 모두 필수 네 종류와 검수 서명을 제출한다. 기존 발행 이미지에 대한 소급 검수/차단은 하지 않는다.
- 저장소 자체에 장애가 나면 보존은 보장할 수 없다. 실패를 숨기거나 유료 재시도를 자동 수행하지 않는다. 운영 전 비공개 버킷 접근과 Storage 용량을 확인해야 한다.

## 네이버 기준

네이버는 [D.I.A. 안내](https://help.naver.com/service/5626/contents/22926?osType=COMMONOS)에서 주제 적합도·정보 충실성·독창성 등을, [C-Rank 안내](https://help.naver.com/service/5626/contents/22927?osType=COMMONOS)에서 출처의 신뢰도를 설명한다. 이를 근거로 원고와 이미지의 관계, 구체적인 정보, 가독성에 집중했다. 이미지 수·색상 변화·템플릿 교체만으로 순위나 상담 전환이 오른다고 보장하지 않는다. 법률·광고 표현의 최종 확인은 별도로 필요하다.

## 검증

- `test-blog-image-quality.cjs`: 실제 라우트/렌더러/서명/Storage 어댑터 검증. 외부 AI와 DB는 모의 처리한다. 고품질 기본값, 도표 분기, 복구 캐시, 서명 변조, 보류/재개, 수정 상한, 불확실한 응답의 중복 호출 방지 포함.
- `test-blog-layouts.cjs`: 6 지면 x 2 명암 x 4 역할의 48 PNG, 추가 36개 구성 변주와 5종 도표. 글자 경계/겹침과 비어 있지 않은 픽셀 검증.
- `test-blog-images-ui.cjs`: 독립 이미지 화면의 4장 생성, 보류, 재검수, 원본 ID 재사용, 저장 차단, 1440/390/320px 확인.
- `test-blog-publish.cjs`: 실제 브라우저에서 부분 실패 복구, 승인 서명 제출, 검수 대기 복사 차단, 4장 네이버 HTML, 전화 링크, ZIP, 반응형 확인.
- `test-blog-publish-api.cjs`: 서명 없는 이미지 거절, 변경된 원고/다른 제작 세트의 완료 방지.
- 기존 이미지, 공개 강점, 전화번호, 복사 기능 회귀 테스트도 실행한다.

검수 파일: `C:/클로드/blog-quality-review`. 도판·프로필은 테스트용 합성 자료이며 운영 AI의 실제 결과물은 아니다. 로컬에는 운영 API/DB 키가 없으므로 **실제 유료 모델의 결과 품질·지연시간, 운영 Storage 권한, 네이버 실제 편집기에 붙여넣은 최종 상태는 아직 검증하지 못했다.** 운영 반영 전 대표 분야의 실제 샘플을 확인해야 한다.
