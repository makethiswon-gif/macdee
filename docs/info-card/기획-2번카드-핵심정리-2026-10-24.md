# 블로그 2번 카드 — '핵심 정리' 기획 (2026-10-24)

대표 지시: "블로그 두 번째 사진인 변호사 AI 이미지를 빼고, 두 번째엔 글과 관련한 인포그래픽이나 내용을 쉽게 이해하는 타이포그래피가 들어가게. 세련되고 깔끔하게."

## 1. 결정 요약

| | 지금 | 바꾼 뒤 |
|---|---|---|
| 1번 표지 | 사진 + 흰 제목 (A/B 조판) | 그대로 |
| **2번** | 변호사 스튜디오 AI 사진(변호사마다 1종을 글마다 돌려 씀) | **글 내용을 정리한 카드** — 도표(비교·절차·기준·기간) 또는 타이포(숫자·한 줄 정리). 글마다 다름 |
| 3번 상담 | 변호사 사진 + 전화번호 | 그대로 (변호사 얼굴은 여기 남는다) |

- 이미지 생성 AI 호출 없음. 코드가 그린다(1초 미만). 2번 카드 비용은 0원 그대로.
- 데이터(어떤 형식으로 무엇을 담을지)는 **원고를 쓴 모델이 같은 응답 끝에 12줄로 적는다**(표지 브리프 `===COVER===`와 같은 방식 → `===INFO===`). 추가 호출 없음.
- 본문에 없는 내용은 절대 싣지 않는다. 뽑은 데이터가 검증을 못 넘으면 '한 줄 정리'(글의 결론 문장 + 갈래 2~3개)로 떨어져 카드가 비는 일은 없다.

시안: `docs/info-card/mockups/` — `00-set-preview-*.png`(표지→핵심 정리→상담 세트), `01~05`(형식별), `01b`(어두운 판).

## 2. 디자인 체계 — 세 장이 한 세트로 읽히게

1·3번과 같은 뼈대를 쓴다. 그래서 2번만 따로 논 느낌이 안 난다.

| 요소 | 규격 (설계 1200 → 출력 2000px) |
|---|---|
| 여백 | 72 (표지와 같음) |
| 표제 | 왼쪽 위, 사무소 색 6px 막대 + 28px 굵은 글자 (표지의 표제와 같은 부품). 글의 분야·핵심 검색어 |
| 유형 표시 | 오른쪽 위 22px 회색: 비교 · 절차 · 판단 기준 · 기간 · 숫자로 보기 · 핵심 정리 |
| 제목 | Noto Sans KR 900 60px, 최대 2행 (표지 제목과 같은 서체). 잡지 정체성의 서체가 명조 계열(저널·칼럼형, 예: 카라)인 사무소만 제목을 Noto Serif KR 700으로 → 변호사별 차이. 정음·김정웅·이지은은 고딕(구현: `getMagazineIdentity(profile).typography === "serif"`). **명사형 주제 제목만** — "벌금형과 금고형 집행유예, 의사 면허의 차이", "스토킹 고소 뒤 형사 절차 4단계", "유류분 반환청구 기한 1년과 10년". "~가릅니다 · ~흘러갑니다 · ~사라집니다" 같은 서술형 축약 문장·구호는 쓰지 않는다(대표 지시 2026-10-24) |
| 바탕 | 따뜻한 오프화이트 `#F6F5F0`. 사진 두 장 사이에서 쉬어 가는 지면 |
| 글자색 | 잉크 `#141414`(표지 띠와 같은 검정), 보조 `#6B6B66`, 괘선 `#D9D6CE` |
| 사무소 색 | 표제 막대 · 번호 · 강조 열 · 큰 숫자에만. 면을 칠하지 않는다 |
| 하단 | 한 줄 메모(22px 회색, 본문의 주의 문장) + 사무소명 24px (표지 하단과 같은 자리) |
| 금지 | 그라데이션 · 그림자 · 아이콘 · 일러스트 · 둥근 상자 (기존 지면 규율 그대로) |
| 세로 균형 | 본문 높이를 먼저 재고, 남는 공간을 행 사이에 나눠 넣는다(최대 1.8배). 항목이 2개든 5개든 아래가 비지 않는다 |

어두운 판(`#141414` 바탕, 시안 01b)도 같은 규격으로 나온다. 기본은 **밝은 판** 권장 — 사진(어두움)·정리(밝음)·사진(어두움) 리듬이 가장 잘 읽힌다. 썸네일 A/B처럼 변호사별로 고정할 수도 있다.

## 3. 여섯 형식과 고르는 규칙

| 형식 | 쓰는 때 | 시안 |
|---|---|---|
| 비교 compare | 두 갈래 대조 (벌금형 vs 금고형, 합의 vs 소송) | 01 오승준 |
| 절차 flow | 순서가 있는 것 (조사 → 결정 → 처분 → 재판) | 02 양영희 |
| 판단 기준 checklist | 챙길 것·따지는 기준 목록 | 03 카라 |
| 기간 timeline | 시점이 있는 것 (사고일 · 합의 시한 · 공소시효) | 기존 데이터 모델 그대로, 시안 생략 |
| **숫자로 보기 numbers** (새로) | 글의 핵심이 수치 1~2개일 때 (1년/10년, 7일, 2년) | 04 카라 |
| **핵심 정리 statement** (새로) | 도표 구조가 없을 때의 기본값. 주제 제목 + 짧은 안내 한 줄 + 갈래 2~3개 | 05 이지은 |

- 원고 모델이 본문을 보고 하나를 고른다. 항목 2~5개, 항목 22자·설명 34자 이내(기존 `infographic.ts` 상한 그대로).
- 숫자·조문·기한은 본문에 적힌 것만. 상식으로 채우지 않는다.
- 기존 '구간 tiers'는 '숫자로 보기'에 흡수한다.
- 승소·보장·'전문' 같은 광고 규정 위험 표현은 카드에서 걸러 낸다(원고 규칙과 같은 필터).

## 4. 데이터가 오는 길 (비용 0)

1. **원고 응답** `===INFO===` 블록(원고 모델이 작성, 출력 토큰 약 300 → 편당 1원 미만). `lib/blog-cover-brief.ts`와 같은 꼴의 `lib/blog-images/info-brief.ts`로 읽는다.
2. 블록이 없거나 깨지면 → 기존 `INFOGRAPHIC_SYSTEM` 한 번 호출(Sonnet 5.5 사고 최소, 약 $0.01).
3. 그것도 안 되면 → '핵심 정리'(표지 브리프의 question·thesis에서 갈래를 뽑는다. 제목은 글 제목의 명사형으로).
4. 구성안(`planEditorialThreeFromBrief`)의 info 카드에 데이터가 실리고, 이미지 단계는 호출 없이 바로 그린다.

네이버 포스팅 쪽(`naver.mjs prepare` → `02-info.png`)은 바뀐 PNG를 그대로 받는다. 바꿀 것은 아래 두 가지뿐.

## 6. 일정

- **1단계 (반나절~하루)**: 렌더러 + INFO 브리프 + 플랜 연결 + 관리자 표시. 시험은 로컬 렌더(무료)로 형식 6종, 실제 원고 1편 발행(원고 비용만).
- **2단계**: 관리자에서 항목 글자 수정, 어두운 판 변호사별 A/B, 기간(timeline) 시안 다듬기.

## 7. 대표가 정할 것

1. 바탕: 전부 밝은 판으로 갈지, 썸네일처럼 변호사별 밝은/어두운 판을 나눌지. (권장: 밝은 판)
2. 네이버 2번 카드의 'AI 활용' 표시를 끌지. (권장: 끔 — 코드 조판이라 생성 이미지가 아님. 글 내용은 AI가 뽑은 것이지만 이미지 생성과는 다름)
3. 명조 제목(명조 계열 사무소, 예: 카라)을 쓸지, 전부 고딕으로 통일할지. (권장·결정: 명조 유지 — 변호사별 차이가 생김)
4. 1단계 적용 범위: 다음 원고부터 전체 변호사 일괄 적용. (권장)
