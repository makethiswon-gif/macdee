# 블로그 공장(Blog Factory) 기획서

> 작성 2026-08-29 · 대표 지시: "블로그 대행 8곳 루틴을 한 페이지로, 최대한 자동화"
> ⚠️ 기획 문서다. 기존 관리자 화면·API는 전부 보존한다(§6.2.2) — 새 페이지를 추가할 뿐 기존 것을 바꾸지 않는다.

---

## 1. 현재 루틴과 문제

대표의 실제 루틴 (업체 8곳 × 월 쿼터만큼 반복):

| 단계 | 현재 도구 | 수동 작업 |
|---|---|---|
| 1. 원고 생성 | /admin/claude-blog-write | 재료 입력 → 생성 → 복사 |
| 2. 이미지 생성 | /admin/blog-images | 원고 붙여넣기 → 변호사 선택 → 카드 생성 → 다운로드 |
| 3. 네이버 검수·포스팅 | 클립보드 복사 or publisher/publish.mjs | 검수·수정 → 붙여넣기 or 로컬 스크립트 실행 |
| 4. 맥디 변호사 블로그 반영 | /blog/[slug] (contents 테이블) | **완전 수동 붙여넣기** |

코드 조사로 확인된 사실:

- **/admin/blog-publish 가 이미 1~3단계를 한 화면에 통합**해 놓았다(주제 추천 → 원고 → 저장 → 카드 4장 → Storage 업로드 → status `ready`). 그런데 **포스트 1건씩 수동 클릭**으로만 돌아간다. 8업체 × 월 n건이면 클릭 지옥.
- 4단계는 **파이프라인이 아예 없다**: `blog_posts`(관리자·네이버용)와 `contents`(맥디 블로그가 읽는 테이블)는 어떤 키로도 연결돼 있지 않다. `blog_profiles.id`(TEXT)와 `lawyers.id`(UUID)를 잇는 매핑 자체가 없다.
- /admin/blog-images 는 구세대 단품 도구(다운로드/ZIP 전용, 원고 선택 드롭다운은 UUID/TEXT 불일치로 고장). blog-publish 가 같은 백엔드를 쓰는 현행 흐름이다.
- 네이버 발행은 공식 API가 없어 ①클립보드 복사(수동 붙여넣기) ②로컬 Playwright(publisher/publish.mjs, 프로필별 chrome_profile) 두 갈래. publish.mjs 는 **1건씩 수동 실행**해야 한다.

## 2. 목표

> **"쿼터 채우기" 버튼 하나 → 검수만 사람이 → 네이버·맥디 반영은 자동.**

- 8업체의 월간 진행 상태가 한 화면에 보인다.
- 원고·이미지 생성은 배치(일괄)로 돌아간다 — 대표는 결과만 검수한다.
- 검수 승인 후: 네이버는 로컬 퍼블리셔가 자동으로 집어가고, 맥디 블로그에는 서버가 자동 반영한다. 4단계 수동 붙여넣기는 소멸.

## 3. 새 페이지 — /admin/blog-factory

기존 blog-publish 를 대체하지 않고 별도 페이지로 추가한다(보존 원칙). 구성:

```
┌─ 상단: 업체(프로필) 8칸 스트립 ─────────────────────────────┐
│ [혜안 3/8] [고구려 5/8] [카라 8/8✓] [새록 2/8] …            │  ← 월 쿼터 게이지
│                                    [이번 달 쿼터 채우기 ▶] │  ← 핵심 버튼
├─ 좌: 파이프라인 테이블 (선택 업체 or 전체) ─────────────────┤
│ 제목/주제        원고  카드  검수  네이버  맥디             │
│ 이혼 재산분할…   ●     ●     ◐     -      -    [열기]      │
│ 음주 측정 거부…  ●     ●     ●     ●      ●    [링크]      │
├─ 우: 검수 패널 (행 클릭 시) ────────────────────────────────┤
│ 제목 편집 · 본문 편집(형광펜/밑줄 프리뷰) · 카드 4장 미리보기│
│ [반려·재생성] [수정 저장] [✓ 승인 → 발행 대기]              │
└─ 하단: 백그라운드 작업 로그 (생성 진행/실패 재시도) ────────┘
```

- **쿼터 채우기**: 프로필별 `monthly_quota - publishedThisMonth` 만큼 → 주제 추천(`blog-posts/topics`, 최근 40건 중복 회피 내장) → 원고(`claude-blog-write`, DNA 적용) → 카드(`blog-images/generate-design` × imageCount) → 저장까지 **순차 배치 실행**. 페이지 안의 숨김 렌더 영역에서 html-to-image 래스터화(현행 방식 그대로 — 서버 인프라 추가 없음). 진행률/실패는 하단 로그에.
- **검수 패널**: draft_body↔polished 비교, 인라인 수정, 카드 개별 재생성. 승인 버튼이 곧 발행 신호다.
- 기존 API 를 그대로 재사용한다 — 신규 API 는 아래 3개뿐.

## 4. 자동화 설계 — 단계별

### 4-1. 원고+이미지 (완전 자동화)
기존 API 재사용, 페이지가 오케스트레이션. Anthropic/Replicate 요율 고려해 프로필당 직렬·전체 2-병렬, 실패 건 자동 1회 재시도.

### 4-2. 검수 (사람이 하는 유일한 단계)
status 흐름 확장: `draft → ready → **approved** → publishing → published → failed`.
승인 없이 발행되는 경로는 만들지 않는다(법률 콘텐츠 — 검수는 자동화 대상이 아님).

### 4-3. 네이버 발행 (반자동 → 자동)
공식 API 부재 → Playwright 유지하되 **watch 모드** 추가:

```
node publisher/publish.mjs watch   # 대표 PC에서 상주
```
- 30초 간격으로 `status='approved'` 폴링 → 순차 발행 → `published`+naver_url 회신.
- 계정 보호: 프로필당 발행 간격 랜덤(5~15분), 실패 2회면 `failed`로 두고 페이지에 "클립보드 복사" 폴백 버튼 노출.
- 발행 시간대 지정(예: 09~18시만) 옵션.

### 4-4. 맥디 변호사 블로그 반영 (완전 자동화 — 신규)
- **스키마**: `blog_profiles.lawyer_id UUID NULL` 컬럼 추가(마이그레이션 014). 관리자 설정 화면에서 프로필↔lawyers 1회 매핑.
- **신규 API** `POST /api/admin/blog-posts/sync-site`: published 전환 시(퍼블리셔가 호출, 또는 페이지의 "맥디 반영" 버튼) `contents`에 insert — `lawyer_id`(매핑), `channel='blog'`, `status='published'`, slug 자동 생성, 본문은 네이버 강조 문법→HTML 변환(기존 `blog-naver-html.ts` 변환기 재사용), 카드 이미지 URL 포함. `blog_posts.site_synced_at` 기록.
- 중복 방지: `contents`에 `source_post_id` 컬럼(또는 slug 규칙)으로 멱등 처리.
- SEO 유의: 네이버 원문과 동일 본문이 자체 블로그에 실리므로, sync 시 제목 변형+canonical 처리 옵션을 둔다(중복 콘텐츠 페널티 방지 — to-naver 라우트가 이미 같은 고민을 리라이트로 풀고 있음. 1차는 그대로 싣고, 2차 개선으로 "라이트 리라이트" 토글 검토).

### 신규 API 요약 (3개)
1. `POST /api/admin/blog-factory/batch` — 쿼터 계산+생성 큐 킥오프(또는 클라이언트 오케스트레이션이면 생략 가능)
2. `PATCH /api/admin/blog-posts` — status CHECK 에 `approved` 추가(마이그레이션 014)
3. `POST /api/admin/blog-posts/sync-site` — contents 반영

## 5. 하지 않는 것

- 네이버 공식 API 연동(존재하지 않음), 검수 없는 자동 발행, 기존 blog-publish/blog-images 페이지 제거(보존), portal_firms 와의 통합(거래처 개념 통합은 별도 과제 — blog_profiles 이 사실상의 업체 축).

## 6. 단계별 구현 계획

| 단계 | 내용 | 규모 |
|---|---|---|
| P1 | /admin/blog-factory 페이지: 8업체 스트립 + 파이프라인 테이블 + 검수 패널 + 배치 생성(기존 API 오케스트레이션) | 1.5~2일 |
| P2 | 마이그레이션 014(lawyer_id 매핑, approved 상태, site_synced_at) + sync-site API + 프로필 매핑 UI | 0.5일 |
| P3 | publisher watch 모드(간격 랜덤·시간대·폴백) | 0.5~1일 |
| P4 | 품질: 월간 발행 리포트, 주제 중복 대시보드, 라이트 리라이트 토글 | 이후 |

**P1+P2 만으로 루틴이 "버튼 → 검수 → 승인"으로 줄어든다.** P3는 대표 PC에 상주 프로세스 하나 띄우는 것으로 네이버까지 무인화.

## 7. 리스크

- **네이버 자동화는 비공식** — 계정 제재 가능성. 간격 랜덤화·시간대 제한·수동 폴백으로 완화하되, 제재 시 클립보드 모드로 즉시 회귀 가능해야 함(이미 있음).
- **이미지 배치의 브라우저 의존** — html-to-image 가 페이지 열림을 요구. 배치 중 탭을 닫으면 중단(진행 상태는 DB에 있으므로 이어하기 가능하게 설계).
- **콘텐츠 중복(SEO)** — 네이버↔맥디 블로그 동일 본문. 1차는 수용, 트래픽 붙으면 리라이트 토글로 전환.
