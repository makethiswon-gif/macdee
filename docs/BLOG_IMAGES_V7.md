# 블로그 시각 편집기 V7

후속 변경: 마지막 장의 인물 중심 상담 레이아웃과 링크 복사 기능은 `docs/BLOG_IMAGES_V8.md` 참고. 아래는 V7 도입 시점의 기록이며 이후 상담 카드는 생략하지 않고 사진·연락처를 요구하도록 변경했다.

작성: 2026-09-06. V6 이후의 로컬 개편. 이 문서 작성 시 운영 배포·커밋·고객 데이터 변경은 하지 않았다.

## 방향

주제와 무관한 사진을 채우는 이미지 생성기가 아니라, 원고를 읽고 독자의 이해를 돕는 설명 자료를 구성하는 편집기로 변경했다. AI는 매 원고에 맞는 시각물을 새로 생성할 수 있고, 법률 표현·한글·브랜드 정보는 별도 렌더링한다.

기존 문제는 `photo-generator.ts`가 원고 전체를 해석하지 않고 일부 키워드로 준비된 장면 중 하나를 선택했던 점이다. V7에서는 이 장면 선택 로직을 제거했다.

## 사용 순서

1. `/admin/blog-images`에서 변호사와 최종 원고를 선택하거나 붙여넣는다.
2. `구성안 먼저 보기`로 질문·핵심·각 이미지 역할·삽입 위치·원문 인용을 확인한다. 시각물 장면을 직접 수정할 수 있다. 바로 제작하려면 `기획하고 이미지 만들기`를 누른다.
3. 표지·설명·마무리 3장이 기본이다. 보조 시각물은 선택 사항이며, 근거가 부족한 카드에는 생략 사유를 표시한다.
4. `본문에 넣어 보기`에서 문단 사이 배치를 검수한다. 네이버 에디터의 실제 렌더링을 복제한 화면은 아니다.
5. 제목·레이아웃 수정은 기존 시각물을 재사용한다. 새 그림이 필요할 때만 `시각물 새로 생성`을 누른다.
6. PNG 개별 저장 또는 PNG와 삽입 안내가 포함된 ZIP을 저장한다. 법률 표현과 연락처를 사람이 확인한 뒤 발행한다.

원고 수정 중에는 이전 완성본을 보존하고 이전 결과임을 표시한다. 새 전체 제작이 시작되면 이전 세트를 교체한다. 화면 새로고침에 대비한 영구 초안 저장은 이번 범위에 포함하지 않았다.

## 처리 구조

- `/api/admin/blog-images/plan`: 원고 전체(최대 40,000자)를 문단으로 나누고 Claude Sonnet 5가 한 세트를 기획한다. 앞 3,000자만 사용하는 방식이 아니다.
- `visual-planner.ts`: 문단 ID, 실제 원문 인용 일치, 원고 해시, 카드 중복, 항목 수·길이를 검증한다. 조건을 잘라내는 대신 잘못된 구성안을 거절한다. 독자용 카피와 내부 기획 설명을 구분하도록 지시한다.
- `/api/admin/blog-images/generate-design`: 공유 구성안에서 카드 한 장을 생성한다. 기존 호출의 호환을 위해 구성안이 없으면 기획할 수 있으나, 이미지 편집기·블로그 발행·블로그 공장은 모두 구성안을 한 번 받아 공유하도록 변경했다.
- `photo-generator.ts`: GPT Image 2에 해당 원고의 대상·관계·장면·제외 조건을 전달한다. 그 뒤 Claude의 이미지 입력으로 기획과의 적합성·잘못된 문서/글자·심각한 형태 왜곡을 확인한다. 실패하면 보류하며 자동 유료 재생성은 하지 않는다.
- `brief-renderer.ts`: Canvas와 등록 한글 폰트로 제목·본문·로고를 직접 합성한다. 이미지 모델에 한글 타이포나 실제 고객/증거를 그리게 하지 않는다.

AI 시각물은 사진 또는 편집 일러스트 중 원고에 맞게 기획한다. 실제 사무실 사진 사용 옵션도 유지했으며, 이 경우에는 AI 생성·적합성 검수를 호출하지 않고 직접 검수하도록 안내한다. 실제 변호사 사진과 로고는 등록 자산을 그대로 사용한다.

## 디자인

- 선명한 대비 / 밝은 페이퍼 브리프 두 가지 편집 스타일.
- 표지는 큰 제목과 편집 일러스트·사진, 긴 제목은 문구를 바꾸지 않고 줄 길이를 균형 있게 조정.
- 순서도는 번호·연결선, 타임라인은 시점 축, 체크리스트는 타일, 비교는 좌우 대조, 구간은 범위 블록으로 각각 다르게 표현.
- 홀수 체크리스트 마지막 항목은 가로 전체를 사용.
- 마무리는 핵심 문장과 실제 프로필·연락처. 등록되지 않은 직함을 임의로 붙이지 않는다.
- 폭 1,024px, 내용에 따른 높이(최대 2,800px), 불투명 PNG. 넘치는 내용은 잘라 저장하지 않는다.

## 비용·오류·안전 경계

- 기본 AI 세트: 텍스트 기획 1회 + 이미지 생성 1회 + 이미지 적합성 검수 1회. 보조 시각물을 선택하면 이미지 생성과 검수 각각 1회 추가. 설명/마무리 렌더링 자체는 이미지 모델을 호출하지 않는다.
- 구성안만 확인해도 텍스트 모델 비용은 발생한다. 제목/레이아웃 변경은 이미지 AI를 재호출하지 않는다.
- 검수 실패 또는 응답 유실 후 다시 시도하면 새 생성 비용이 발생할 수 있다. 서버 영구 캐시는 이번 범위에 없다. 숨겨진 재시도·구형 모델 폴백은 하지 않는다.
- 재사용 시각물은 현재 원고 해시와 일치해야 한다. 압축 JPEG 원본을 완성 PNG와 함께 돌려줘 서버 응답 용량을 제한한다.
- 모든 신규 API는 기존 관리자 인증을 요구한다. 외부 자산은 기존 허용 저장소 또는 업로드 이미지로 제한한다.
- 원문 인용 검증은 인용 문자열이 원문에 존재하는지 확인하는 검사다. 요약의 완전한 의미 일치나 법률적 사실 검증을 보장하지 않는다. AI 이미지 검수 역시 사람이 하는 최종 검수를 대체하지 않는다.
- 화면에서 보여주는 문단 배치는 다운로드 안내/미리보기다. 네이버 자동 발행이나 기존 블로그 본문에 이미지를 자동 삽입하는 기능은 추가하지 않았다.
- 기존 프로필의 원고 조회 오류는 별도 문제다. 직접 붙여넣기 작업과 오류 메시지를 분리했고, 원고 조회 API/DB 스키마를 변경하지 않았다.

- 렌더링만 하는 API 요청의 AI 호출 0회.
- 주제 불일치 이미지 보류, 429 오류에서 자동 중복 요청 없음.
- 전체 원고의 마지막 문단까지 기획 요청에 포함되는지 확인.

`node scripts/test-blog-images-ui.cjs C:/클로드/blog-images-v7-qa`

로컬 3100 포트의 합성 API 응답을 사용하는 브라우저 회귀 검사. 구성안/근거/장면 수정, 단일 구성안 공유, 부분 실패 후 개별 재시도, 원본과 바이트가 같은 PNG 저장, ZIP, 제목/레이아웃 수정 요청, 문단 삽입 위치, 이전 결과 보존, 새 세트의 제목 초기화, 1440/390/360px 가로 넘침을 검증한다. 실제 고객 생성/발행은 실행하지 않는다.

실제 API 검수도 가상 원고 3종(진료 기록과 보험 서류, 개인정보 유출 안내 문자, 상담 자료 원본과 정리본)으로 수행했다. GPT Image 2 표준 품질로 생성한 표지 3장이 모델 적합성 검수를 통과했고, 완성본을 직접 확인했다. 사용자 실제 원고에서의 품질 보증이나 고품질 모드 전체 회귀를 뜻하지 않는다.

- `--live`: 세 가상 원고의 기획만 새로 요청한다(텍스트 API 비용).
- `--live-art`: 저장된 기획으로 세 표지의 실제 생성·검수를 요청한다(유료). 기획 파일이 없으면 먼저 기획한다.
- `--recompose`: 저장된 기획과 시각물로 재합성한다. 새 AI 호출 없음.
- `scripts/test-blog-images.cjs`는 V7 테스트의 호환 진입점이다.

검수 출력: `C:/클로드/blog-images-v7-qa`. API 키·고객 데이터는 검수 출력에 저장하지 않았다.

추가 확인: TypeScript 검사, 변경 핵심 파일 ESLint, 위 회귀 검사, Next.js 프로덕션 빌드 모두 통과했다. 이미지 생성 라우트의 빌드 추적에 한글 폰트와 Canvas 네이티브 모듈이 포함됐다. 기존 middleware 명칭 사용에 대한 Next.js 경고는 남아 있으며 이번 변경과 무관하다. 이번에 변경한 기존 파일의 `git diff --check`는 통과했고, 사용자 변경인 `.gitignore`의 끝 빈 줄 경고는 그대로 보존했다.
