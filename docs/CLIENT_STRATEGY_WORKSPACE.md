# 클라이언트 요청함 · 대표 월간 전략실

2026-09-07 요청: 로펌이 등록한 상담·사례 자료와 요청사항을 종합하여 월 1회 마케팅 전략과 포스팅 주제를 대표에게 제공한다.

## 화면과 운영

- `/portal`: 기존 접속 코드 로그인 유지. `요청사항` 메뉴에서 제목·내용·분야·우선순위·선택 희망일 입력. 고객은 자기 로펌 요청 원문과 상태만 확인한다.
- `/portal?tab=marketing`: `마케팅 정보` 메뉴에서 홈페이지·호스팅·FTP, 네이버 블로그·플레이스·광고, Instagram·Threads·Meta, Google·YouTube·측정, 카카오, 담당·승인·브랜드 기준을 로펌별로 관리한다.
- `/admin/client-strategy`: 기존 관리자 로그인 사용. 서버에서 관리자 권한을 확인한다. 월별·로펌별 보고서와 전체 기간 요청함을 분리한다.
- 요청 상태: 접수 / 진행중 / 완료 / 보류. 상태 변경은 고객에게 보이고 **내부 메모는 대표에게만 보인다**.
- 요청함: 로펌·상태·제목/본문 검색, 페이지네이션. 우선순위 필터는 명시적으로 현재 페이지에 적용한다.
- 보고서: 종합 판단, 자료 신호, 실행 우선순위, 주제/키워드/검색 의도/작성 방향/채널, 요청 요약, 추가 확인 사항. 주제는 검색·복사 가능하다.
- AI 초안은 고객에게 자동 공개하지 않는다. 광고 집행·포스팅·메시지·이메일 발송을 연결하지 않는다.

## 월간 집계 규칙

Vercel Cron `/api/cron/client-consulting`, `0 0 1 * *` = 매월 1일 09:00 한국시간. 기존 주간 이메일 리포트 작업을 대체한다. 다른 매거진·결제 크론은 변경하지 않는다.

전월 **등록 시각** 기준 상담/사례 자료와 메시지, 전월 업무일자를 가진 업무일지, 전월 요청 및 그보다 오래된 미완료 요청을 로펌별로 수집한다. 사건이 발생한 달을 추정하지 않는다. 과거 요청 상태는 생성 당시 현재 상태다. 이후 월에 등록한 자료는 이후 월간 집계로 들어간다.

관리자 수동 생성도 종료된 달만 허용한다. `(firm_id, report_month)` 유일 키와 3분 lease/claim token으로 동시 호출·재실행을 제어한다. 완료/자료 없음 보고서는 보존하고, 실패 또는 중단된 작업만 재시도한다. 생성 중 표시는 조회로 갱신하며 3분 이상 지난 작업은 재시도할 수 있다.

전체 적격 자료는 페이지 끝까지 읽고 건수를 대조한다. 입력량 예산 때문에 세부 본문 일부만 발췌할 경우 집계는 유지하고 보고서의 보완사항에 누락 범위를 고지한다. 원문은 원래 자료함/요청함에 남는다. 자료가 전혀 없으면 AI 호출 없이 `자료 보완 필요`로 저장한다.

## 모델과 실행 제한

- 기본 `claude-sonnet-5`, 선택적으로 서버 환경변수 `PORTAL_STRATEGY_MODEL` 지정. 기존 `ANTHROPIC_API_KEY` 사용, 다른 기능의 모델 설정은 변경하지 않는다.
- 모델 ID는 [Anthropic 공식 모델 문서](https://platform.claude.com/docs/en/models/overview)에서 확인했다.
- 원문은 명령이 아닌 비신뢰 근거로 취급한다. 직접 식별정보 기본 마스킹, 출력 근거 ID 검증, 과장·성과 보장·가짜 수치 금지.
- 자동 마스킹은 완전한 익명화를 보장하지 않는다. 업로드 전에 식별정보를 제거하고, 실제 사건 공개·광고 사용 여부는 별도 확인한다.
- 업체당 75초, 실제 AI 요청 60초(응답 본문 수신까지), 크론 전체 250초, 최대 동시 3곳. 실패/미처리가 있으면 크론은 503을 반환하고 개별 완료 결과는 보존한다.
- GET 조회는 AI 호출이나 새 보고서 생성을 하지 않는다. 관리자 POST만 수동 생성하며 동일 출처를 검사한다. 크론은 `CRON_SECRET` 전용이다.

## 데이터베이스

`016_portal_requests.sql` → `017_portal_strategy_reports.sql` → `018_portal_marketing_profiles.sql` 순서. 기존 고객 데이터 수정·삭제 없이 요청, 전략, 마케팅 정보 테이블과 `claim_portal_strategy_report` 함수만 추가한다.

계정·비밀번호는 `PORTAL_CREDENTIALS_KEY`로 AES-256-GCM 암호화한 단일 봉투만 DB에 저장한다. 로펌의 일반 조회는 저장 여부만 반환하고 비밀번호 원문은 반환하지 않는다. 대표 관리자만 동일 출처의 별도 요청으로 일시 확인할 수 있으며, 암호문은 로펌 ID에 결합되어 다른 로펌 ID로 복호화되지 않는다. 빈 비밀번호 입력은 기존 값을 보존하고 명시적 삭제만 제거한다. 초대·대행 권한을 제공하는 플랫폼은 비밀번호 공유보다 초대를 우선한다.

RLS 활성화. anon/authenticated 직접 권한 차단. 서비스 역할만 서버의 검증된 API를 통해 접근한다. 고객 응답에서는 내부 메모를 명시적 필드 목록으로 제외한다. 관리자 전략 조회는 접속 코드 세션으로 접근 불가하다.

배포 전 조건: 016/017/018 적용과 함수 확인, Production `CRON_SECRET`, `ANTHROPIC_API_KEY`, `PORTAL_CREDENTIALS_KEY` 존재 확인. 이번 점검에서 필요한 변수의 등록을 확인했으며 비밀값은 출력하지 않았다.
